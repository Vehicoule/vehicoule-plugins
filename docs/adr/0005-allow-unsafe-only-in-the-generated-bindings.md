# 0005. Allow `unsafe` only in the bindings that wit-bindgen generates

- Status: Proposed
- Date: 2026-11-07
- Deciders: the user

## Context

- Vehicoule forbids `unsafe` (`unsafe_code = "forbid"`, its AGENTS.md rule 9); `forbid` cannot be lifted for one
  module.
- The guest side of the contract is generated by `wit-bindgen` 0.63.0's `generate!` and `export!` macros
  ([ADR 0001](0001-write-plugins-in-rust-as-wasm-components.md)). Built for `wasm32-unknown-unknown` with
  `unsafe_code = "forbid"`, the template fails with "usage of an `unsafe` block", "declaration of an `unsafe`
  function" and "usage of the unsafe `export_name` attribute", all inside the macros' output, and with Clippy's
  `same_length_and_capacity` (`Vec::from_raw_parts`) under `clippy::all` (tried on 2026-11-07, in this repository's
  template, toolchain 1.99.1). Built natively with the `export!` call left out, only Clippy's lint remains.
- Built natively, a `cdylib` with the exports does not link: the export names hold `:` and `@`
  (`cabi_post_vehicoule:plugin/plugin@0.1.0#describe`), which the native linker's version script rejects (same try).
- The host's own test plugins avoid the question by living in a workspace with no lint table (Vehicoule,
  `crates/vehicoule-plugin-host/fixtures`). Here the plugins are the product: their own code needs every lint.

## Options

1. **`unsafe_code = "deny"` in the workspace, and one `#[expect]` on the `bindings` module, with its reason.**
   `expect` fails the build if the lint stops firing, so the exception cannot outlive its cause. Hand-written code
   stays under the same lints as in Vehicoule.
2. **Plugins without the workspace lints.** No exception to write; no lint on the plugins' own code either.
3. **Write the bindings by hand, without `unsafe`.** Not possible: the exports are `unsafe` by nature (the component
   ABI passes raw pointers).

## Decision

Option 1, recommended:

- The workspace sets `unsafe_code = "deny"`. Every other lint is Vehicoule's.
- Each plugin has one module, `bindings`, holding only the `wit_bindgen::generate!` call and, for
  `target_arch = "wasm32"` only, `export!`. It carries `#[cfg_attr(target_arch = "wasm32", expect(unsafe_code, reason
  = …))]` and `#[expect(clippy::same_length_and_capacity, reason = …)]`, citing this ADR.
- No other `expect` or `allow` of `unsafe_code` anywhere; review checks it, and the template shows the form.

## Consequences

- A `wit-bindgen` bump that changes which lints its output triggers fails the build until the `expect` list matches,
  in the bump's pull request.
- The exports exist only in the Wasm build: natively, the tests call the plugin's functions directly
  ([`docs/plugin-crates.md`](../plugin-crates.md), section 2).
